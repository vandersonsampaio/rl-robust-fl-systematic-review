# Reliability procedure and reconciliation rules

## Reviewers and rounds

R1 (the first author) screened all records, assessed all full texts, extracted all data and scored quality. R2 (the second reviewer) checked samples blindly in two rounds. In round 1, R2 worked without a written codebook. In round 2, R2 worked with the written codebook and the full texts. Agreement is always computed against R1's coding **before** consensus. The summary is in `interrater_agreement.csv`, and the decision-level data are in the files listed there.

| round | check | files |
|---|---|---|
| 1 | calibration: 20 records stratified by R1 decision (10 proceed, 10 exclude), excluded from kappa (A12) | `stage1_sample_key.csv` |
| 1 | stage 1: blind random sample of 811 records, 20% of 4,054, rounded up and drawn among the 4,034 records outside calibration with a fixed seed (A13) | `stage1_blind_sample.csv`, `stage1_sample_key.csv` |
| 1 | stage 2: 36 exclusions and 16 inclusions; RQ2 of the 52 studies with comparisons; quality of 16 studies (A16) | `r2_round1_*.csv`, `stage2_consensus.csv` |
| 2 | blind recoding of RQ2 (same 52 studies) and quality (26 studies: the 16 from round 1 and 10 new ones) with the written codebook (A19) | `r2_round2_*.csv`, `r2_round2_sample_key.csv` |

During stage 1, a one-row offset was found in 145 consecutive R2 decisions. The decisions were realigned, R2 decided the skipped row again, and the original spreadsheet was kept by the authors (A13).

## How disagreements were resolved

1. Disagreements were discussed between R1 and R2, with access to the full text.
2. When a disagreement came from a point the codebook left open, the rule adopted was written down. The rule was dated as an amendment and applied to **all** studies, not only to the one that raised it.
3. Category changes in favour of R2 and their effect on the counts are recorded in the amendments and in `original_pt/analise_qp2_R2v2.md` and `original_pt/analise_qualidade_R2v2.md`.
4. The R2 copy of the codebook (`codebook/codebook_v2_as_sent_to_r2_pt.md`) was not changed after it was sent. Rules adopted later appear only in R1's copy (`codebook/codebook_v2_r1_pt.md`).
5. A sensitivity analysis (`sensitivity_analysis.md`, generated by `scripts/sensitivity.py`; original in `original_pt/sensibilidade_qp2_qa.md`, before amendment A27) recomputes the central RQ2 and quality counts under the alternative readings of the boundary cases and under R2's coding before consensus. Conclusions A–E of the paper hold in every scenario.

## RQ2 coding rules (codebook §2, with amendments)

**Non-learned policy.** A policy inside the agent's own action space whose decision rule is fixed before execution. The following do not count as non-learned policies:

- external robust aggregators that replace the whole defense;
- other FL algorithms;
- centralized training;
- learned baselines;
- methods from other papers;
- references with **no defensive action**, such as FedAvg, simple averaging, or accepting or selecting all clients (A20).

In terms of the paper's notation, the admissible class Π₀ contains policies with access to no more information than the agent, which need not use that information. Fixed actions are therefore admissible, and oracles are not.

**Categories and precedence.** When a study has several comparisons, its category is the strongest one, in this order:

| category | criterion |
|---|---|
| same-signal heuristic | fixed rule (threshold, top-k, ranking, weighting) applied to the same signal or score the agent observes |
| fixed action | the same action in every round, not depending on the signal, and itself a defense |
| different-signal heuristic | fixed rule using information the agent does not receive |
| random | selection or weights drawn at random in the same action space |
| partial ablation | variant without the agent in which the substitute decision is not described |
| oracle | uses information unavailable to the agent (knows the malicious clients, best rule chosen in hindsight, retraining from scratch) |
| none | only external aggregators, other FL algorithms, learned methods or references with no defensive action |

The oracle is outside Π₀, so it does not displace an admissible reference: it sets the category only when it is the only reference, and any oracle comparison is still recorded (`rq2_has_oracle`). Before amendment A27, the oracle came right after the same-signal heuristic. That earlier order is the one used to compute the R1 × R2 agreement.

**Result of the comparison** (closest comparisons only):

| result | criterion |
|---|---|
| tie | difference up to about 1 percentage point in the main metric in some regime, or the agent does not beat the reference in every regime; a loss is counted with ties |
| narrow win | the agent leads by more than about 1 and up to about 6 percentage points |
| clear win | the agent leads by more than about 6 percentage points, or by a large margin in another metric |

These definitions are refined by A21:

- **Numbers prevail over text.** The authors' wording decides only when there are no legible numbers or the difference is within the reading error of a figure.
- **Main metric.** The main metric is the utility of the global model under attack. Under a targeted attack, it is the attack metric (ASR or accuracy on the attacked class). If the agent and the reference are not compared on utility, it is the metric of the agent's own decision.
- **Variability and tests.** Whether the comparison reports variability across seeds, and whether a statistical test is applied to that comparison, are recorded separately. A test applied to other comparisons in the same study does not count.

**Discussed as a finding** (A21) is read literally. It is S when the authors comment on the result of the strongest comparison and draw any conclusion from it, P when they only mention it, and N when it is absent or there is no comparison. For ties, whether the authors acknowledge the equality is recorded separately.

## Quality rules (codebook §3, with amendments)

- **Missing information.** Undocumented items are scored as not met. For QA2, QA3, QA7 and QA9, the tables separate zeros caused by missing reporting from documented deficiencies.
- **QA4 (A24):** the code must be accessible without intermediation (public repository or journal supplement) and contain the agent and the experiment (attacks and configuration). Each declared link was opened, and the check is recorded in `extraction/original_pt/code_availability_check_pt.md`. Code available only on request, without a link or behind a broken link scores P, and incomplete code also scores P.
- **QA5 (A23):** S for a same-signal heuristic or a fixed action that is a defense. P for random, different-signal heuristic, oracle or partial ablation. N for no non-learned comparison.
- **QA7 (A20):** S requires both the agent's training volume and at least one optimization parameter.
- **QA8 (A19):** the server-side-data family counts only defenses that actually use server-side data (FLTrust, Zeno, root or validation data). Detection defenses that do not use server-side data count in neither family.
- **QA2 (A23, correction):** S requires at least three runs. Mean ± SD without the number of seeds scores P.
